## pitlane-mcp v0.14.0 — a freshness feed, a token budget, and a doctor for the index

This release makes the index something agents can reason about instead of blindly trusting: every content change advances a revision that navigation responses report, a new feed lists exactly which symbols changed since a revision, `ensure_project_ready` can keep the index fresh with a background watcher, and `investigate` accepts a token budget that turns overflowing answers into navigation targets instead of silent drops. A new `pitlane doctor` diagnoses and safely repairs unhealthy indexes, and calls embedded in macro arguments are finally visible to the navigation graph. Four features and one fix landed; the test suite grew from 628 to 670 tests.

### Index revisions and a change feed (#82)

Every persisted content change — fresh indexing, watcher batch flush, full resync — advances a monotonic index revision persisted alongside the index. All eleven navigation responses (`locate_code`, `read_code_unit`, `trace_path`, `analyze_impact`, `navigate_code`, `find_usages`, `find_callers`, `find_callees`, `get_file_outline`, `get_symbol`, `investigate`) now carry `index_revision`, so callers can tell whether the answer they are reading reflects the current source.

A new `get_index_changes(project, since_revision)` tool lists revisions newest-first with symbol-level diffs (`added`/`removed`/`modified`), distinct `changed_symbols`, and a `complete` flag; the log is bounded to the latest 50 revisions with per-list caps and explicit `truncated` markers. A revision becomes visible once the index flush lands — pending embedding work never delays it. On top of this, `ensure_project_ready` starts a background watcher by default (`watch: false` to opt out), so edits are picked up incrementally after startup and the reported status appears in the response.

### Token-budgeted investigations (#83)

`investigate` accepts an approximate `token_budget` (default ~6000 tokens). Symbols are inlined in discovery order; when the budget runs out, the next symbol is truncated to what still fits (never below a usable minimum) and the rest become metadata-only navigation targets — every candidate stays in `symbols` with its ID, file, and line range plus a `presentation` field, and budget-omitted symbols appear in `omitted_symbols` with the reason. A caller whose context does not fit can fetch what was cut with `read_code_unit` without re-discovering. An `include_tests` flag also pulls related test symbols into investigations that would not otherwise surface them.

### Diagnostics and safe repair (#86)

`pitlane doctor` (MCP tool and CLI subcommand) reports per-check index health — index loads, meta validity, freshness against the same mtime-snapshot logic the cached path uses, exclusion-pattern validity, oversized skipped files, embedding store compatibility and completeness, and change-log state — each with a status, detail, and a targeted repair hint. `repair: true` applies only safe repairs: a force re-index when stale, background re-embedding when vectors are incomplete. Repairs touch rebuildable artifacts only, never user files.

### Watcher lifecycle across processes (#99)

The CLI watcher can now be managed from anywhere: it publishes a status file under the index directory, and `pitlane watch --status` reports `running` (with PID), `stale` (cleaned up on read), or `not_running`, while `pitlane watch --stop` requests a clean shutdown that flushes pending edits first. Starting a second watcher over a live one returns `already_running` with the owner PID. The mechanism uses a status file and a stop flag — no signal handling, identical behavior on all five platforms.

### Macro-embedded calls are visible in the graph

Calls inside macro arguments such as `format!("{}", helper(x))` were invisible to the navigation graph: tree-sitter parses macro token trees as raw tokens, and generic identifier evidence was capped below the `calls` threshold. Call-shaped evidence — a direct `name(` occurrence for an unambiguous callable in comment- and string-stripped source — is now call-grade, so `callers`/`callees` see macro-embedded call sites. A latent edge-bucket deduplication bug that this exposed was also fixed.

### Validation

- 670 Rust tests pass; formatting and Clippy checks pass on Linux x86_64, Linux ARM64, macOS Apple Silicon, macOS x86_64, and Windows x86_64.
- Freshness feed verified live: add/modify/delete each produced the correct revision and diff within one second of the edit.
- Doctor verified live on a genuinely stale index: flagged, repaired with `--repair`, and healthy again.
