## pitlane-mcp v0.17.0 — compact `analyze_impact` responses, correct provenance, and a packaged-crate test guard

`analyze_impact` now returns a ranked blast-radius overview instead of a graph dump. On the dense ripgrep fixture the response drops from 51,512 to 13,123 serialized bytes (a 75% reduction) while the traversal ranking, scores, and selected symbols are unchanged. Provenance is now derived from structured graph edges rather than formatted reason strings, so an edge that appears in both the symbol and file views is counted once — the top-level summary for that same query falls from 43 calls / 279 references to the true 15 / 11. Alongside that, the top-level evidence counters stop under-reporting when `limit` drops symbols, the response baseline fixture moves inside the published crate, and the repository's Git and pull request conventions are written down. **This is a breaking response-shape change for `analyze_impact` consumers — see Breaking changes below.**

### `analyze_impact`: bounded, deduplicated evidence (#129, #130, #131)

Each impacted symbol now reports its complete deduplicated `evidence_count` and provenance totals but serializes at most the two highest-ranked `support_edges`; `omitted_evidence_count` reports the remainder. The unbounded free-form `reasons` arrays are gone, and file entries are summary-only — a file reports `score`, `usage_count`, `confidence`, and `impacted_symbol_count` without repeating symbol-level evidence.

Provenance is counted from structured edge relations (`calls` vs `references`) over a stable edge identity of `(impacted symbol, via symbol, direction, relation)` instead of substring-matching `" calls: "` and `" references: "` in presentation strings. Repeated call sites from one caller and diamond-shaped paths no longer double-count, and per-symbol provenance is computed from the complete evidence set before display truncation, so provenance no longer changes when display evidence is compacted.

`limit` applies independently to the ranked `impact_symbols` and `impact_files` lists, which is now documented for both the tool and the `pitlane analyze-impact` CLI.

For the pinned ripgrep query: 323 reason entries (22,808 bytes) and 61 support-edge entries with 18 duplicates become 0 reason entries and 20 support edges with 0 duplicates.

### Breaking changes

`analyze_impact` response shape:

| Field | Change |
| --- | --- |
| `impact_symbols[].reasons` | removed |
| `impact_symbols[].support_edges` | capped at 2, deduplicated (was 3, undeduplicated) |
| `impact_files[].reasons` | removed |
| `impact_files[].support_edges` | removed |
| `impact_files[].provenance` | removed |
| `impact_files[].impacted_symbol_count` | added |
| `impact_symbols[].evidence_count`, `omitted_evidence_count` | added |
| `total_evidence_count`, `omitted_evidence_count`, `evidence_truncated` | added at top level |
| per-symbol `provenance` | counted from deduplicated structured edges, so repeated call sites from one caller count once |

`analyze_changes` inherits the same per-revision impact shape and now always emits the evidence counters and `edge_provenance_summary`, including on revisions with no changed symbols.

No re-index is required: index schema, symbol and relationship extraction, embeddings, and index compatibility are untouched. Restart the MCP server normally and let `ensure_project_ready` run its usual freshness check — `force=true` is unnecessary.

### Fix: top-level evidence counters now span every impacted symbol

The counters added by #129 were computed after the symbol list was truncated to `limit`, so they described only the returned symbols while `omitted_impact_symbols` next to them was a global figure. A response returning 1 of 685 symbols reported `omitted_impact_symbols: 684` alongside `omitted_evidence_count: 3`, and evidence belonging to the dropped symbols was neither counted nor flagged. `total_evidence_count` now covers every impacted symbol before truncation, `omitted_evidence_count` is derived as `total - serialized`, and `evidence_truncated` reflects symbols dropped by the limit as well as per-symbol support-edge truncation. For the ripgrep fixture the counters move from 26 total / 6 omitted to the accurate 880 total / 860 omitted, of which 20 are serialized.

### Fix: the ripgrep response baseline now ships inside the crate

The baseline integration test loaded its fixture with `include_str!("../bench/baselines/...")`, but `Cargo.toml` excludes `bench/` from the published crate. `cargo package` verification builds only the library and binaries, so publishing succeeded while `cargo test` on the published crate failed to compile with `couldn't read tests/../bench/baselines/analyze-impact-ripgrep.json`. The fixture and its README now live under `tests/baselines/`, and `docs/development.md` records the rule that test fixtures must live under `tests/`.

### CI: the packaged crate's tests are built on every run

A new `package-verify` job runs `cargo package` and then builds the extracted package's tests, which is what actually catches fixtures that fall outside the crate. The existing `cargo test` matrix never exercised that path.

### Docs: Git, commit, and pull request conventions

`AGENTS.md` and `docs/development.md` now document the branch, commit, and pull request naming rules this repository follows: Conventional Commit branch prefixes such as `fix/` or `feat/`, Conventional Commit subjects with the pull request number appended once it exists, and the same subject reused as the pull request title.

### Validation

- 800 Rust tests (797 passed, 3 ignored) across the library, CLI binary, server binary, and integration suites; Clippy (`--all-targets --all-features -- -D warnings`) and `cargo fmt --check` clean on Linux x86_64/ARM64, macOS Apple Silicon/x86_64, and Windows x86_64.
- New regression coverage for repeated-path and diamond dedup, high fan-in output bounds, evidence counters spanning symbols omitted by `limit`, the `total == serialized + omitted` invariant, and the `analyze_changes` empty-revision response shape.
- Pinned ripgrep baseline (ripgrep 14.1.1 @ `4649aa97`) re-measured on the pre-fix revision to confirm the reported starting point: 51,512 serialized bytes, 323 reason entries, 22,808 reason bytes, 18 duplicate structured edges, and a 43/279 summary that double-counted symbol and file aggregates. The fixed revision measures 13,123 bytes with no serialized reasons and no duplicate structured edges; the 3-byte difference from the earlier 13,120 measurement is the wider evidence counter values.
- The evidence counters were also checked end-to-end on a high-fan-in query (685 impacted symbols, `limit 1`) to confirm they report the omitted symbols rather than the returned one.
- Release binaries built from the `v0.17.0` tag by the release workflow; Homebrew formula updated automatically.
