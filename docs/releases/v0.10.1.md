## pitlane-mcp v0.10.1 — cache correctness, watcher search freshness, and safer repository walks

This patch release tightens the indexing pipeline after the v0.10.0 navigation overhaul. It focuses on making repeated indexing reliably use the cache, ensuring watch-mode updates correctly refresh BM25 search, and improving behavior on large or messy repositories with generated/vendor directories and unreadable paths.

### Correct index cache freshness

`index_project` now records enough source metadata to reliably distinguish a stale index from a reusable one.

The cache freshness check now tracks:

- source file mtimes with nanosecond precision
- directory mtimes
- the eligible source-file count
- supported files that contain no symbols

This fixes a regression where a freshly re-indexed project could still be treated as stale on the next run, especially when the repo contained supported source files with no extracted symbols.

Existing indexes may rebuild once because the on-disk metadata version changed. After that, unchanged projects should return `status: "cached"` as expected.

### Watch-mode BM25 search freshness

`watch_project` now correctly marks the BM25 search index stale after watcher-driven updates.

Previously, the watcher removed the old BM25 ready sentinel name while the current BM25 index used `.ready.v2`, which meant incremental watch updates could leave BM25 search results stale until a forced rebuild. The watcher now uses a shared BM25 stale-marker helper, so the next search rebuilds from the updated symbol index.

A regression test now covers this path by indexing a file, updating it through the watcher reindex flow, and verifying BM25 search finds the new symbol.

### Custom directory exclusions

A new `PITLANE_EXCLUDE_DIRS` environment variable lets you add process-wide directory-name exclusions without changing every tool call.

```sh
PITLANE_EXCLUDE_DIRS=vendor,tmp,generated pitlane-mcp
```

These exclusions are applied consistently across project indexing, file search, and content search. Directory names are case-insensitive and only simple directory names are accepted.

### More resilient repository walking

Repository walks now handle unreadable entries more gracefully. Instead of failing or silently discarding too much state, pitlane logs walkdir errors and continues indexing/searching accessible files where possible.

This improves behavior on real-world checkouts that contain permission-restricted directories, generated dependency trees, or platform-specific artifacts.

### CI and quality checks

Clippy coverage is now aligned across CI and pre-commit configuration:

```sh
cargo clippy --all-targets --all-features -- -D warnings
```

This ensures optional targets and feature-gated code are covered by the same lint pass locally and in CI.

### Dependency updates

This release includes patch updates for:

- `clap`
- `libc`
- `blake3`
- `tree-sitter-c`
- `tree-sitter-c-sharp`

The tree-sitter updates refresh C and C# parser crates; the release was smoke-tested against repository indexing and parser discovery paths.

### Documentation refresh

The README and docs were reorganized to make the project easier to scan:

- tool guidance moved into dedicated docs
- language support documented separately
- benchmark and security notes split out
- agent guidance updated for the current public tool tier

### Validation

This release was tested with the full Rust test suite, stricter clippy checks, and targeted smoke tests on benchmark repositories.

Notable smoke checks:

- `bench/repos/ripgrep` indexes and immediately returns cached on repeat indexing.
- `bench/repos/guava` force-indexed successfully with 3,275 files and 56,805 symbols, then returned `status: "cached"` on the next unchanged run.
