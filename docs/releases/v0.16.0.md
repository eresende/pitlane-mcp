## pitlane-mcp v0.16.0 — knowledge-base indexing, OKF metadata-aware search, and full-document/section reads

This release adds the knowledge half of the index: Markdown becomes a first-class searchable surface alongside code. Documents (READMEs, docs, runbooks, skills) are split into heading-aware sections, indexed lexically, embedded for semantic search, and — when they carry Open Knowledge Format (OKF v0.2) front matter — searched with metadata-aware filters and ranking. A new `read_knowledge_document` tool serves whole documents or single sections with their OKF metadata and link graph, and the one-shot `pitlane` CLI gains `search-knowledge` and `read-knowledge-document` subcommands. Three feature phases and a follow-up fix landed; the test suite grew from 692 to 789 tests (787 pass, 2 ignored).

### Knowledge search over Markdown (#119)

`search_knowledge` queries the project's Markdown knowledge base (docs, READMEs, runbooks) for a natural-language information need. Documents are modeled as heading-aware `KnowledgeDocument`s with a section outline, indexed incrementally from current files via BM25, and embedded by a small embedding pipeline for semantic ranking. Results are per-section with hierarchy, line coordinates, title, and snippet, returned at mixed lexical/semantic scores with graceful lexical fallback when embeddings are unavailable, plus steering guidance toward `read_knowledge_document`.

### OKF v0.2 metadata-aware indexing and search (#120)

Documents carrying OKF v0.2 front matter are treated as concepts: full YAML front matter becomes typed metadata — provenance (`generated`, `verified`), trust tier (unverified / machine-confirmed / human-reviewed derived from `verified` actors), lifecycle (`status`, `stale_after`), `sources`, `resource`, and `okf_version`. `search_knowledge` filters on all of it (`okf_type`, `status`, `min_trust`, `tag`, `path_filter`) and ranks with metadata adjustments (+0.05 human-reviewed, −0.05 deprecated, −0.10 stale, −0.02/−0.03 draft). Relative Markdown links resolve into a `related_docs` link graph whose incoming edges (`referenced_by`) surface on reads. Representative OKF v0.2 bundle fixtures anchor integration tests (conformance, curation faults, provenance/trust shapes).

### Reading documents and sections (#121)

New `read_knowledge_document` tool returns a document's raw source Markdown with front matter, OKF metadata, a section outline with line coordinates, `related_docs`, and `referenced_by` — or a single section by slug (`preamble`, a heading slug like `computation`, or a full `knowledge:path#slug` id). Missing documents and sections produce friendly errors (the latter listing available sections). The one-shot `pitlane` CLI now exposes `search-knowledge` and `read-knowledge-document` with the same filters (`--tag`, `--path-filter`, `--okf-type`, `--status`, `--min-trust`, `--limit`); being one-shot, it refreshes the knowledge index and regenerates embeddings synchronously when the store is missing or stale, so semantic ranking still works on the CLI.

### Fix: date-only `stale_after` now marks documents stale

OKF §5.5 names a bare `YYYY-MM-DD` for `stale_after` — a concept is stale on/after that day. The parser only accepted full RFC 3339 timestamps, so date-only values silently parsed as never-stale: the stale flag stayed false, the −0.10 ranking penalty was skipped, and stale documents surfaced at the top of results. `stale_after` now accepts strict `YYYY-MM-DD` (as UTC midnight of that day, matching the reference implementation's `today >= stale_after`) while RFC 3339 timestamps remain supported and the basic (`20260101`) and week (`2026-W01-1`) forms stay rejected.

### Validation

- 789 Rust tests pass (787 passed, 2 ignored) across the library, CLI binary, server binary, and integration suites; formatting and Clippy clean on Linux x86_64/ARM64, macOS Apple Silicon/x86_64, and Windows x86_64.
- Verified end-to-end against a real OKF v0.2 bundle (`bench/repos/okf`, the okf skill repository): 2043 knowledge sections indexed with embeddings; semantic, tag, okf-type, status, min-trust, and path-filter searches round-trip over both MCP and the CLI; full-document and single-section reads return raw source with OKF metadata and the link graph.
- The `stale_after` fix is covered by new date-only/spelling unit tests and by date-only cases in the `search_knowledge` and `read_knowledge_document` stale-reporting tests.
