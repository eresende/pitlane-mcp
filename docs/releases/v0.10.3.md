## pitlane-mcp v0.10.3 - bounded session state, cached investigations, and agent ergonomics

This patch release focuses on making the v0.10.x agent-navigation surface steadier under repeated use. It bounds per-session memory growth, improves repeated `investigate` calls, tightens regex search guardrails, and makes agent-facing output easier to read.

### Bounded project session state

pitlane now caps the number of project session records retained in memory and prunes older entries with an LRU policy.

This keeps long-running MCP sessions from accumulating unbounded per-project state as agents move across many repositories. The in-session `investigate` cache is also capped so repeated high-level investigations remain useful without growing indefinitely.

Recency scoring now ages against each project session's own recent activity instead of unrelated global session traffic. This keeps recent symbols, files, and directories stable even when other indexed projects are active in the same server process.

### Cached investigate answers

Successful `investigate` responses are now cached for repeat lookups in the same session.

When an agent asks a similar question again, pitlane returns the cached investigation payload with explicit guidance to drill into a specific symbol using `read_code_unit` when more detail is needed. Failed investigations are not cached, so indexing or setup errors can be fixed and retried normally.

### Clearer agent-facing output

Navigation answers now display paths relative to the project root instead of relying on `src/` or `crates/` path fragments. This makes results easier to scan in repositories with different layouts.

Structured error hints now point agents toward `ensure_project_ready` as the default startup path, matching the current public-tool guidance.

### Regex search guardrails

Regex content search now rejects overly long patterns and applies a regex compile-size limit.

This keeps accidental or hostile regex searches from consuming excessive work during content lookup, while preserving normal literal and regex search behavior.
