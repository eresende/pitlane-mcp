## Smarter tool routing for behavioral queries

When `locate_code` returns no results for a natural-language query (e.g. "start a game server container when user requests it"), it now suggests using `investigate` instead.

### Problem

Models sometimes pick `locate_code` for intent-based questions where `investigate` is the better tool. Since `locate_code` is designed for concrete targets (symbol names, file paths, keywords), these queries return empty results with no guidance on what to do next.

### Fix

The empty-results response now detects behavioral queries (4+ words, not a symbol name or path) and includes a hint:

> "This looks like a behavior or intent question. Try investigate(query="...") instead — it discovers relevant symbols and inlines their source for natural-language questions about what the code does."

This nudges the model toward the correct tool on the next turn without changing any routing logic or tool behavior.
