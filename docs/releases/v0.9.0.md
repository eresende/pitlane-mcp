## pitlane-mcp v0.9.0 - smarter startup, better discovery, Solidity support, and safer workspace boundaries

### Smarter startup and discovery

This release makes pitlane much easier to boot up and navigate from an agent workflow.

A new `ensure_project_ready` tool provides a preferred one-call startup path by combining indexing with conditional embedding waits, so agents can get to a usable project state with less orchestration.

Discovery also got a major upgrade. `search_content` adds indexed literal and regex code lookup, which helps agents stay inside pitlane instead of falling back to shell grep. `search_files` improves repository navigation by supporting filename, path fragment, fuzzy, and glob-based lookup. And `trace_execution_path` adds a new way to answer behavior-level questions with compact execution-path summaries, layered symbols, edges, snippets, confidence scoring, and noise filtering.

On top of that, `search_symbols` and `search_content` now return stronger next-step guidance, helping agents refine searches instead of repeating overly broad queries.

### Safer filesystem boundaries

pitlane now supports filesystem access control through `PITLANE_ALLOWED_ROOTS`.

This adds an explicit path policy layer so tools can be restricted to approved roots, with support for platform-specific separators on Unix and Windows. File-level operations now reject invalid traversal and disallowed absolute paths, and access denials return clearer guidance when a request falls outside policy.

The result is a safer default story for editor, agent, and multi-workspace setups where tool access should stay scoped to known directories.

### Better behavior tracing and cross-platform correctness

`trace_execution_path` was introduced in this release, and it also received follow-up fixes to make path handling more reliable across platforms.

Windows-style backslashes are now normalized in execution-path comparisons and related scoring logic, which makes symbol classification, entry detection, noise filtering, and path matching behave consistently across Windows and Unix-like systems.

Embedding-related test behavior was also tightened up by replacing hardcoded batch assumptions with dynamic effective batch sizing.

### Solidity support

pitlane now supports Solidity through `tree-sitter-solidity` (thanks @0kn0t).

This adds parsing and symbol extraction for contracts, interfaces, libraries, functions, methods, modifiers, constructors, events, errors, structs, and enums from `.sol` files. Solidity can also be targeted through the language filter using `solidity` or `sol`.

Support was further expanded with extraction for `fallback` and `receive` functions, so common Solidity entry points are now indexed as first-class symbols as well.

Benchmark coverage was updated alongside this work, including OpenZeppelin Contracts v5.6.1 in the corpus and documenting a strong Solidity result.

### CLI and workflow improvements

The CLI was expanded and documented to match more of the current tool surface.

New commands and improvements include:

* `usages` for finding symbol call sites
* `lines` for fetching specific line ranges
* `wait-embeddings` for blocking until embeddings complete
* `watch` for keeping the index current
* `usage-stats` for token-efficiency reporting
* `--max-files` on `index`
* `--path`, `--max-dirs`, and `--summary` on `outline`

The README, CLAUDE.md, and tool descriptions were also refreshed to reflect the current workflow, the updated tool hierarchy, and the recommendation to prefer pitlane-native discovery over shell-based lookup.

### Indexing and schema polish

`index_project` now treats `max_files=0` the same as omitting the field entirely, resolving both to the default cap.

This aligns implementation behavior with the MCP schema and avoids surprising behavior for clients that send zero to mean “use the default”.

### Tests and quality

This release includes focused regression coverage for startup flows, content search, file search, execution-path tracing, Solidity extraction, path policy enforcement, and default indexing behavior.

Overall, v0.9.0 is a strong step toward making pitlane easier to start, easier to search, safer to expose, and more useful across real multi-language agent workflows.
