## pitlane-mcp v0.13.1 — eight correctness fixes for stale answers, false calls, and exclusion drift

This release closes every correctness issue in the tracker: investigate answers no longer go stale or leak across filters, semantic search keeps vectors current when code changes, the navigation graph no longer invents calls from comments or unrelated same-name symbols, and watcher updates finally obey the exclusion policy. Eight fixes landed, each with regression coverage; the test suite grew from 610 to 628 tests.

### Investigate answers stay fresh and honest (#73, #80)

`investigate` previously keyed its cache on normalized query words only, so a Rust-only request could be served a cached answer produced for Python, and reindexing an edited file kept returning the old source. The cache key now includes the language filter, scope filter, and a per-project index epoch that is bumped on every reindex and watcher update.

Capped responses no longer claim completeness. Responses now carry explicit limit metadata — per-symbol line ranges with `lines_shown`/`lines_total`, `truncated_symbols`, `omitted_symbols` with actionable `read_code_unit` pointers, and a `complete` flag — and the closing guidance states the truncation counts instead of asserting that the shown source is the complete implementation.

### Embeddings refresh when the code changes (#75)

A stable symbol ID was treated as proof that its embedding vector was current: editing a function's documentation or body without renaming it left a stale vector in place after ordinary reindexing. The embedding store now records a per-symbol document hash and regenerates vectors whenever the document changes, prunes vectors for deleted symbols, and skips unchanged documents during watcher updates. The store format moves to version 3, so the first run after upgrading performs a one-time full re-embedding.

### Navigation graph: fewer false calls, faster rebuilds (#76, #79)

A Python comment containing `authenticate_user()` produced ~0.98-confidence `calls` edges to both a Python function and an unrelated Rust function. Comments and string literals are now stripped from call evidence, candidate resolution is restricted to the referencing symbol's language, and names shared by multiple same-language candidates are capped below the `calls` threshold so they stay classified as references.

Watcher updates no longer rebuild the entire navigation graph per changed file — one rebuild per batch — and candidate lookup uses a name-to-candidate index instead of scanning every symbol per source symbol, removing both quadratic hotspots.

### One exclusion and filter policy everywhere (#74, #78)

Watcher-driven indexing applied no exclusions: a file excluded at initial indexing re-entered the index as soon as it was edited, and full resyncs dropped custom patterns and `.gitignore` entries. Effective exclusions are now persisted with the index and reused by both the batch and full-resync watcher paths; previously indexed files that become excluded are removed. Symbol-search `file` filters now match project-relative paths consistently across all modes, so `--file auth.py` works without a `**/` prefix while absolute patterns keep working.

### Stability (#77)

Byte slicing such as `&sig[..100]` panicked the CLI when a truncation boundary landed inside a multibyte character. All four response-formatting truncation sites now cut at character boundaries; ASCII behavior is unchanged.

### Validation

- 628 Rust tests pass, including new regression fixtures for every fix.
- Formatting and Clippy checks pass on Linux x86_64, Linux ARM64, macOS Apple Silicon, macOS x86_64, and Windows x86_64.
