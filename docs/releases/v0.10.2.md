## pitlane-mcp v0.10.2 - source symlink hardening and dependency updates

This patch release tightens source-file path handling after the v0.10.x navigation and indexing work. It makes the source discovery policy explicit: pitlane rejects symlink-backed source files instead of following them during indexing, searching, or read-time access.

Thanks to @tamlut-modnys for the symlink-hardening contribution in #33.

### Reject symlinked source files

pitlane now rejects source files whose path is backed by a symlink, even when the symlink itself lives inside the project.

This closes a class of path-confusion issues where an apparently in-project source file could resolve somewhere else at read time. The policy is now applied across the main file-entry points used by the MCP tools:

- project indexing
- file search
- content search
- symbol search
- usage search
- symbol graph loading from existing indexes

The implementation uses shared path-policy helpers so discovery and read boundaries enforce the same rule.

### TOCTOU-resistant reads

Source reads now re-check symlink state at the point where file content is opened. This avoids relying only on earlier directory-walk validation, which could be invalidated if a path changes between discovery and read.

Existing indexes are also filtered when loaded so older cached index data cannot reintroduce symlink-backed source paths after upgrading.

### Regression coverage

The test suite now makes the source symlink policy explicit with regression coverage for:

- symlink escape attempts
- in-project symlinked source files
- canonical path handling
- cached index loading with symlink-backed entries
- tool-level filtering in search and usage paths

This is intended to keep the behavior consistent across macOS, Linux, and Windows-compatible code paths.

### Dependency updates

This release includes patch updates for:

- `tantivy`
- `rayon`
- `tokio`
- `rmcp`
