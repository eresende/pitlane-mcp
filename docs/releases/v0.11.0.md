## pitlane-mcp v0.11.0 — richer semantic indexing, hybrid ranking, and transparent diagnostics

This release substantially improves natural-language-to-code retrieval. Pitlane now embeds richer, bounded symbol documents, combines semantic similarity with focused lexical and metadata evidence, and exposes the scoring details needed to distinguish embedding failures from ranking failures.

The changes were developed against a repeatable llama.cpp benchmark. Compared with the previous `nomic-embed-text` pipeline, hit@1 improved from 0.50 to 0.75, hit@3 from 0.75 to 1.00, and mean reciprocal rank from 0.6333 to 0.8333 while preserving hit@5 at 1.00.

### Richer symbol embedding documents

The default `metadata_code` profile replaces the old name-and-signature-only representation with a structured document containing the relative file path, symbol name, qualified name, kind, language, signature, documentation, identifiers extracted from the complete symbol, and a bounded head/tail source excerpt.

Documents remain size-bounded to avoid allowing very large functions to dominate an embedding. Two additional profiles are available: `metadata` omits identifiers and source, while `legacy` reproduces the previous representation for controlled comparisons.

Pitlane also supports configurable query and document task prefixes. `auto` mode applies Nomic-compatible prefixes when appropriate, while explicit prefixes and a no-prefix mode keep the behavior model-independent and configurable.

### Hybrid semantic ranking

Semantic similarity remains the primary signal, but candidates can now receive bounded adjustments from:

* identifier and metadata overlap
* BM25 rank
* callable symbol-kind preference
* file-path role

Tests, examples, vendored code, and third-party dependencies receive soft penalties for implementation-oriented queries rather than being excluded. Those penalties are disabled when the query explicitly asks for tests or examples.

Cross-query session boosting is now disabled by default. This prevents symbols seen during an earlier search from becoming artificially sticky for unrelated queries, which was one cause of repeated low-value results.

`locate_code` now preserves the final semantic ranking order instead of reordering candidates after retrieval, and `investigate` continues through the same improved search path before reading source.

### Transparent semantic diagnostics

The new `semantic_debug` search mode exposes the complete ranking calculation for each result, including:

* raw cosine similarity
* final hybrid score
* BM25 rank
* lexical, symbol-kind, path-role, and session adjustments
* file, symbol, and symbol kind

This makes it possible to inspect whether an unexpected result came from the embedding itself or from later ranking adjustments.

### Safer embedding storage and model changes

Embedding metadata now fingerprints the model, vector dimension, document profile, size limits, and query/document prefixes. Changing any of these settings invalidates the incompatible cache and triggers a rebuild.

Pitlane L2-normalizes document and query vectors, validates dimensions before storage and search, and uses cosine similarity as a dot product over normalized vectors. OpenAI-compatible embedding responses now honor their explicit response indices, preventing out-of-order API responses from assigning vectors to the wrong symbols.

Existing semantic indexes may rebuild once after upgrading because the document format and cache identity have changed.

### Repeatable llama.cpp retrieval benchmark

The new `bench/semantic_retrieval.py` harness tests semantic retrieval directly without an LLM or fallback symbol/content search masking weak results. It records exact top-ten rankings, raw and final scores, hit@1, hit@3, hit@5, and mean reciprocal rank.

The initial benchmark covers GPU layer offloading, KV cache allocation, embedding pooling strategies, and OpenAI-compatible embedding request handling. With the same `nomic-embed-text` model, the improved pipeline produced:

* hit@1: 0.50 → 0.75
* hit@3: 0.75 → 1.00
* hit@5: 1.00 → 1.00
* mean reciprocal rank: 0.6333 → 0.8333

### Configuration

New environment variables provide modular control over document construction and ranking:

* `PITLANE_EMBED_DOCUMENT_PROFILE`
* `PITLANE_EMBED_MAX_CHARS`
* `PITLANE_EMBED_BODY_CHARS`
* `PITLANE_EMBED_MAX_IDENTIFIERS`
* `PITLANE_EMBED_TASK_PREFIX_MODE`
* `PITLANE_EMBED_DOCUMENT_PREFIX`
* `PITLANE_EMBED_QUERY_PREFIX`
* `PITLANE_SEMANTIC_LEXICAL_WEIGHT`
* `PITLANE_SEMANTIC_BM25_WEIGHT`
* `PITLANE_SEMANTIC_TEST_PENALTY`
* `PITLANE_SEMANTIC_AUXILIARY_PENALTY`
* `PITLANE_SEMANTIC_KIND_WEIGHT`
* `PITLANE_SEMANTIC_SESSION_WEIGHT`

See `docs/semantic-search.md` for the complete pipeline, defaults, and benchmark instructions.

### Other changes

* Added regression coverage for document construction, cache compatibility, ranking, vector-response ordering, and semantic result ordering.
* Removed deprecated rmcp logging behavior after the rmcp 2.2 upgrade.
* Updated anyhow, regex, rmcp, tokio, tree-sitter, and the checkout GitHub Action.
